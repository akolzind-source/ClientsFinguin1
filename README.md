# Дорожная карта финансового директора

Одностраничный рабочий кабинет для контроля внедрения управленческой отчётности у одного клиента.

## Возможности

- диаграмма Ганта с надзадачами, подзадачами, сроками, ответственными и статусами;
- базовый план: выбор даты, на которую смотрим, и штриховка сдвинувшихся сроков прямо на диаграмме;
- управленческие решения с поиском, фильтрами, приоритетами и комментариями;
- календарь встреч с плановыми и фактическими датами;
- регулярные задачи с подэтапами, недельной, месячной или квартальной периодичностью;
- прокручиваемый план-факт по месяцам, автоматические статусы и примечания к отклонениям;
- добавление, редактирование и удаление данных прямо на странице;
- автоматическое сохранение без авторизации.

## Публикация в Vercel

1. Импортируйте проект в Vercel как приложение Next.js.
2. Откройте вкладку Storage → Connect Database → Neon (можно оставить префикс переменной по умолчанию, например `DATABASE`) и подключите базу ко всем нужным окружениям.
3. Выполните повторный Deploy.

Приложение само находит рабочую переменную с адресом Postgres (`DATABASE_URL`, `POSTGRES_URL` или любую другую, которую создаст интеграция) — вручную ничего переименовывать не нужно. При первом обращении оно автоматически создаст таблицу `dashboard_state` и заполнит её стартовыми данными.

Без базы данных локальная разработка использует файл `work/dashboard-data.json`; на Vercel постоянное хранение обязательно требует подключённой базы — без неё сохранение вернёт понятную ошибку вместо тихого падения.

## Базовый план

Кнопка «Базовый план» над диаграммой открывает выбор даты: приложение показывает ближайший снимок сроков на эту дату или раньше. Задачи с неизменившимися сроками выглядят как обычно; расхождение помечается штриховкой — поверх полоски, если срок вырос, и за её краем, если сократился.

Снимки снимаются автоматически: при первом за сутки сохранении сервер откладывает сроки задач в том виде, в каком они были до правки. Дни без изменений новых снимков не создают, хранится последние 180 записей. История принадлежит серверу — клиент её не перезаписывает.

Проверить состояние подключения можно на `/api/health` — там видно, какая переменная найдена, к какому хосту идёт подключение и отвечает ли база.

## Локальный запуск

```bash
pnpm install
pnpm dev
```

Проверка перед публикацией:

```bash
pnpm lint
pnpm build
```

Страница намеренно не содержит авторизации: любой посетитель ссылки может изменять данные.
